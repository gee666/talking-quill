# Ordinary unsigned Windows release

Dispatch **Build Windows x64 and ARM64 native setup release candidates** on `master`. There are no inputs, repository secrets, protected environments or baseline-workflow prerequisites. Versions must agree across the source packages.

The workflow runs full source validation and security audits, builds the fresh Windows x64 and ARM64 installers, inspects packages and preserves provenance. On each native hosted architecture, smoke verifies the complete `win-unpacked` or `win-arm64-unpacked` file inventory against the exact installer's authenticated payload. It then runs the real `windows-package-lifecycle.mjs --mode unpacked` checks for application readiness, authenticated helper/owner startup, gateway crash and sequential relaunch. It verifies every runtime file again after execution. Changed, missing or extra files fail the gate.

The distinct `github-hosted-native-runtime` evidence binds the installer hash, provenance, source, architecture and actual smoke run. Coverage records `installerPayload: verified`, `nativeRuntime: exercised`, and installation/UAC as `not-exercised`. There are no invented install or uninstall exit statuses. The test does not claim held-key ownership or interactive input coverage. Logs upload even on failure.

GitHub's elevated hosted runners do not provide a real medium-integrity token in the tested configuration. The production installer's rejection of a direct elevated worker remains unchanged. Default hosted CI therefore does not install, uninstall, simulate UAC or weaken token checks. The existing linked-token installation and manual UAC diagnostics remain separate optional checks. Runtime smoke launches only the provenance-bound packaged runtime, with temporary profiles under project `tmp/`, and refuses non-native or non-hosted execution.

Ordinary assembly consumes the stage script's four-file output, including `RELEASE.json`, without invoking the signed/update assembler. A successful candidate run automatically starts **Publish Windows x64 and ARM64 unsigned owner installers**. Only that publisher has `contents: write`. It authenticates the canonical repository's successful default-branch producer, requires its commit to remain the current `master` tip, downloads that run's artifacts, verifies a new draft's bytes, then publishes and verifies the public latest release and tag. Existing tags/releases are never overwritten.

Only the automatic `GITHUB_TOKEN` is needed. GitHub Actions and both native Windows hosted runner architectures must be available, and repository policy must permit the publisher's declared write permission. The unsigned release contains hashes and measured runtime evidence, not a signed update feed or a claim that installation, UAC, reboot, migration or protected installed acceptance passed.

## Fast native diagnostic

Dispatch **Diagnose hosted Windows production setup launch** with `mode: runtime` and `producer_run_id: 34013671889`, or another authenticated canonical producer containing both package artifacts. It exercises the same native runtime/integrity check without rebuilding or waiting for full source validation. The run uses current diagnostic scripts against the selected producer's exact bytes and does not publish. `mode: installation` retains the optional real linked-token install diagnostic and may correctly fail when no suitable token exists.
