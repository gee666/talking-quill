# Talking Quill user guide

Talking Quill is local-first, system-wide dictation for Windows x64/ARM64 and macOS x64/ARM64. Local Whisper transcribes speech, then Talking Quill attempts to paste the result into the focused target.

Raw stays local. Smart can send the local transcript and context to a configured provider. Talking Quill needs no account, but a provider may require an account, credentials, or payment.

> **Keyboard-owner status:** Windows local packages install only a non-suppressing gateway and a detached same-interactive-user owner. The gateway reconnects through a stable local-only per-WTS-session named pipe or starts the adjacent owner when no eligible endpoint exists. Each connection authenticates ephemeral P-256 keys against kernel peer and immutable installed-release facts. Windows installs no SCM service, LocalSystem runtime, enrollment, maintenance executable, or ProgramData owner state. Same-user code is inside the threat boundary and can interfere with these processes or deny service by taking the session mutex.

## Set up

1. Install the package for your operating system and processor, then open Talking Quill. On Windows, choose **More info → Run anyway** at the unsigned SmartScreen warning, then approve the **User Account Control (UAC)** prompt. The installer is intentionally not Authenticode-signed. Elevation writes the fixed Program Files installation and removes obsolete service state.
2. In Welcome, allow microphone access and run the microphone test.
3. Choose the spoken/source language, then download and verify a local model: Large v3 Turbo is about 1.09 GB; Small is about 250 MB.
4. Optionally configure and test Smart processing. Skip it to use Raw dictation only.
5. Review the five built-in Smart reset defaults and their shortcuts on the Ready screen.

On macOS, allow Accessibility and Input Monitoring for shortcuts and text insertion. Screen Recording is needed only for On-Screen Awareness. **Settings** and **Info** can show Welcome again.

## Profiles and shortcuts

On Windows, the profile shortcuts below become active after the gateway authenticates the same-user owner and completes disabled-first reconciliation. If owner startup fails, capture stays disabled rather than falling back to an in-process hook:

| Profile | Shortcut | Mode |
| --- | --- | --- |
| General | `Alt+X` on Windows, `Option+X` on macOS | Smart |
| Prompt | `Alt+X+P` on Windows, `Option+X+P` on macOS | Smart |
| Prompt to English | `Alt+X+Q` on Windows, `Option+X+Q` on macOS | Smart |
| Markdown | `Alt+X+M` on Windows, `Option+X+M` on macOS | Smart |
| Translate to English | `Alt+X+T` on Windows, `Option+X+T` on macOS | Smart |

Talking Quill has five built-ins and up to thirteen profiles total (eight custom profiles). A shortcut chord uses one or more modifiers plus one or more ordered, simultaneously held A–Z keys. The built-in family intentionally shares `Alt/Option+X`: keep X held while pressing P, Q, M, or T for the longer profiles, then release the final suffix and X. The last letter pressed is the **final trigger**. Focus a profile’s shortcut field, hold the modifiers and letter keys in order, then release them. `Tab` and `Shift+Tab` leave the field normally.

Every full chord must be unique, but arbitrary bindings may share a prefix. For example, `Alt+A` resolves on A-up when `Alt+A+B` is also configured, while the longer binding resolves as soon as B goes down. Only the five exact default built-in chords are reserved for their built-in owners; other `Alt/Option+X`-prefixed chords are configurable. Built-ins can be edited or reset but not deleted. Each profile selects Raw or Smart and may add a Smart prompt. `Shift` is only a modifier in the chord; only the final trigger’s down/up timing chooses dictation length.

**Version 21 profile migration:** The upgrade preserves the existing General processing mode and its compatibility mirror; it never changes a Raw user to Smart or enables provider processing, including after completed setup with a cloud provider configured. Fresh installs and an explicit General reset use the new Smart default. Exact old General and Prompt defaults receive the new chord data and may receive updated, privacy-safe prompt text, but the prompt remains dormant while General is Raw.

The five built-ins permanently reserve their reset-safe `Alt/Option+X`, `Alt/Option+X+P`, `Alt/Option+X+Q`, `Alt/Option+X+M`, and `Alt/Option+X+T` defaults. Historical Version 21 migration used the narrower validation rules of that release: a noncanonical profile using `Alt/Option+X` or a same-modifier prefix was deterministically reassigned to the first free `Alt/Option+A–Z` chord while preserving its ID, name, processing mode, and Smart prompt. Current shortcut validation does not apply that historical prefix restriction to new edits. Review migrated shortcuts in **Settings → Dictation profiles**.

On Windows and macOS, global detection treats candidate letters transactionally: modifier edges normally pass through, candidate prefix/trigger letters are temporarily suppressed, successful activation discards them, and an unsuccessful keyboard candidate replays them once in order; the macOS adapter also orders replay before captured mouse boundaries. Windows requires and performs dummy-key Alt/Windows menu neutralization; macOS explicitly requires no synthetic neutralization and reports no fictional native records. macOS paste validates exact retained application/window/control/typed-CFRange evidence and selected-range notification epochs across a final neutral-modifier barrier, reinstalls the control observer on every focused-control identity change, and asks the AX worker to set clipboard plain text only in that exact control. Electron binds the request to SHA-256 of the exact UTF-8 fallback text, bounded to the same 1,000,000 UTF-8 bytes as application transcripts. Windows coherently double-samples native foreground/focused-control/caret/input-desktop identity plus a monotonic focus/foreground/caret-change epoch before the first candidate edge and validates it before continuation, replay, and activation start; activation up uses the frozen context to preserve protocol balance. A target change cancels into capture-only drain and never injects a hidden down into the replacement target. Paste uses one submission-time absolute injection deadline and remains Waiting/cancellable through target/modifier validation and stable bounded CF_UNICODETEXT hashing. A minimal final closure rechecks deadline and sequence, then atomically claims Injecting immediately before SendInput; cancellation winning that CAS forbids later injection, while Injecting makes the exact SendInput result authoritative and has a separate bounded completion wait whose expiry reports terminal `indeterminate` authority and forbids retry. Distinct Win32 focus and caret evidence is currently required before capture; Chromium/Electron/custom virtual controls without it remain uncaptured and use ordinary clipboard/manual paste. UI Automation virtual-control identity is not currently claimed because no safe asynchronous UIA cache exists and COM/provider calls are forbidden in the hook. Talking Quill does not read or attempt to reconstruct prior custom/file formats: the single intended fallback-text write replaces the current clipboard contents, and no later restoration can overwrite a newer clipboard change. The macOS worker fences and retains one bounded immutable pasteboard sample with `changeCount`, restores and verifies the retained typed range, and rechecks target epochs, real permissions, Secure Input, the retained scalar clipboard revision, and bounded AX-call budget around claim and mutation; it performs no postclaim conversion/hash, pre-claim rejection remains clipboard-only, and unresolved post-claim acceptance is terminal rather than a contradictory ordinary failure. Any shorter binding with longer configured descendants resolves atomically when its trigger is released if no longer suffix was pressed. Secure-input fields, operating-system-reserved shortcuts, and other system-level combinations are not guaranteed to work.

## Quick and Extended dictation

The modes below use the detached owner on Windows. If that owner is unavailable, use visible application/widget controls; the gateway never substitutes an in-process suppressing hook.

- **Quick:** the final trigger key goes down after the chord prefix and is released before 600 ms. By default, Quick finishes after speech followed by the selected trailing silence (1.0, 1.8, or 3.0 seconds). Automatic finishing can be disabled so an explicit `Enter`, the full activation chord again, or the two-minute safety cap is required. Its widget offers **Cancel**, not Stop.
- **Extended:** keep the final trigger key down for at least 600 ms. Extended streams transcription locally and does not submit on silence. Submit with `Enter`, the full activation chord again, or the widget’s **Stop** button. The cap is 30 minutes.
- Press `Escape` or use **Cancel** through recording, transcription, Smart processing, and pre-commit insertion. The intended text is written to the clipboard once as fallback and is never snapshot/restored afterward; once native paste commits, Talking Quill does not attempt an unsafe undo.

Because General's `Alt/Option+X` is also the family prefix, the helper resolves General when X is released and classifies Quick or Extended from the physical hold duration. Start speaking after the widget appears. The longer P/Q/M/T chords resolve on their suffix key down as usual.

The floating widget shows status and microphone level; Extended also shows elapsed time. Talking Quill attempts to paste the final text into the currently focused target. If native paste dispatch fails, the text remains copied for manual paste.

## Raw, Smart, and privacy

**Raw** keeps captured audio in memory and transcribes it with local Whisper without creating an audio recording file or making a Smart cleanup request. Choose the spoken/source language during Welcome model setup or later in Settings: the pinned local runtime requires this explicit value and does not auto-detect it. Whisper always uses its `transcribe` task, so Raw remains in the source language and never uses Whisper's translate-to-English mode. Raw matches the complete transcript against local Voice Commands, inserting a saved snippet on a match or the Raw transcript otherwise. Custom vocabulary does not affect Raw.

**Smart** also transcribes locally in the configured source language first; audio is not sent to the provider. With Pi selected, Talking Quill may start the configured Pi process and extensions as soon as the accepted Smart session begins listening, but no transcript is sent to Pi until you submit the dictation. General, Markdown, and Prompt ask the Smart model to preserve that language. An ordinary Smart profile with no instruction receives a source-language-preservation fallback. Translate to English asks the Smart model—not Whisper—to translate the locally transcribed text to English, and any explicit profile transformation instruction replaces the fallback. Smart cleanup sends the transcript and cleanup context, including Smart-only vocabulary, saved Voice Command trigger phrases (never their snippets), an optional profile prompt, and an optional On-Screen Awareness screenshot. The request also uses the configured provider, model, and authentication. Provider failure or timeout falls back to Raw, although data may already have been sent.

An exact local Voice Command match skips the Smart cleanup payload, so its transcript and prepared screenshot are not sent. Close, cross-language, or naturally embedded command requests are checked by Smart processing for clear invocation intent; surrounding request language is allowed, while merely discussing or quoting a trigger should remain ordinary dictation. Providers may run locally, on a LAN, or in the cloud; some uncredentialed LAN endpoints may use HTTP. Provider handling, retention, accounts, and charges are external.

### On-Screen Awareness

On-Screen Awareness is off by default and requires a vision-capable model. After recording stops and before Smart cleanup, it captures the full display containing the foreground app, excludes the widget, and sends a JPEG only with Smart. A Voice Command match prevents that prepared image from being sent.

A manually started vision/image-echo test also captures and sends a screenshot; the test image is not retained. Screenshot retention is a separate, off-by-default setting that can keep JPEGs and thumbnails for successful Smart history entries.

## Features and settings

- **Dashboard:** enable/disable dictation, inspect readiness, use a test field, and browse History with details, optional thumbnails, Copy, Delete, Delete all, and Load more.
- **General and profiles:** test shortcuts without recording or insertion; manage profiles, widget size, sounds, launch at login, and close to tray. The tray offers Open, Enable/Disable, and Quit; the window has themes and controls.
- **Recording and model:** select and live-test a microphone, require manual finishing or choose silence detection, and opt into Windows system-audio capture for calls and other apps. System audio is off by default and currently unavailable on macOS. Manage Whisper and choose the spoken/source language here too.
- **Smart processing:** configure/test providers, discover models where supported, and optionally enable vision. Pi adds installation-path and thinking-level settings.
- **Voice Commands and vocabulary:** manage and preview trigger/snippet pairs, Smart-only vocabulary, and text import/export.
- **Privacy and Info:** control future history, 7/30/90-day or no expiry, screenshots, diagnostics, and reset. Info includes update status, permissions, data/log folders, notices, and Welcome. Installed releases check the public GitHub release feed at startup. Windows asks before downloading and installing; unsigned macOS releases provide a manual release-page fallback because a stable Developer ID signature is required for safe automatic replacement.

Supported Smart providers are OpenAI, Generic OpenAI, LM Studio, Local AI, KoboldCPP, Oobabooga Web UI, Docker Model Runner, Lemonade, Microsoft Foundry Local, oMLX, Groq, OpenRouter, Together AI, Fireworks AI, DeepSeek, Perplexity AI, Mistral, Novita AI, CometAPI, PPIO, APIpie, SambaNova, Cerebras, GiteeAI, Minimax, Moonshot AI, Z.AI, xAI, NVIDIA NIM, Privatemode, LiteLLM, Ollama, Pi, Anthropic, Google Gemini, Azure OpenAI, AWS Bedrock, and Cohere. Capabilities vary.

## Local data and network use

Settings, history, models, optional screenshots/diagnostics, temporary data, and the theme stay in Electron’s per-user application storage. Find it with **Info → Open data folder**. Credentials use Electron `safeStorage` and cannot be stored when secure storage is unavailable.

History is enabled by default with no automatic expiry; screenshot retention and diagnostics are off. With diagnostics off, the log may contain only `HELPER_STARTUP_UNAVAILABLE`, `HELPER_STARTUP_INCOMPATIBLE`, `HELPER_RUNTIME_UNAVAILABLE`, or `HELPER_RUNTIME_INCOMPATIBLE`. Activation, startup, shutdown, helper lifecycle, and owner connection details are not persisted. Disabling history or diagnostics stops future collection but leaves existing data. **Reset all application data** removes Talking Quill’s local data and restarts the app, without removing external provider software or models. On Windows, uninstall keeps app data unless deletion is explicitly selected.

Network use includes requested, verified Hugging Face model downloads; provider discovery, tests, and Smart requests; startup and manual GitHub update checks; a Windows release download only after update consent; and external Pi CLI/provider traffic.

## Development

Talking Quill uses Electron, React, TypeScript, a non-suppressing Rust protocol-v10 gateway, and a separate detached keyboard owner. The gateway never links suppressing native adapters; it reaches the owner only through the platform-neutral authenticated owner-protocol client. Protocol v10 requires a bounded `keyboardOwner` snapshot on initialize, ping, and observability, reports detached-owner disposition on shutdown, and never negotiates down to v8. Every fresh owner association validates its instance and lease epoch, checks health, sets session capture off, replaces the full activation snapshot while disabled, and only then enables. It configures up to thirteen profile bindings as `{ profileId, shortcut: { modifiers, keys } }` and uses `off | recording | cancel-only` session-key capture modes. Every activation carries an owner-instance/lease-scoped generation and a nullable, opaque native target token that the main process freezes from the first accepted activation and returns with the paste request; later stop activations cannot replace it. A null token falls back to clipboard-only behavior without native paste dispatch. Target tokens stay in the main process and must not be logged or exposed to renderers. Shared prefixes are supported, exact shortcut duplicates are rejected, and the exact built-in shortcuts remain reserved for their owners. Local Whisper worker protocol v2 requires an explicit validated source language; the worker fixes the inference task to `transcribe`.

Run `pnpm install`, then `pnpm dev`, `pnpm build`, `pnpm typecheck`, `pnpm lint`, `pnpm test`, or `pnpm validate`. Packaging scripts build Windows x64/ARM64 and macOS x64/ARM64 artifacts.

For direct personal-use build/install commands on Windows and macOS, including OS warning/permission steps, first run, verification, repair, rollback, uninstall, troubleshooting, and friend-Mac transfer, see [`personal-use-install.md`](personal-use-install.md).

The macOS owner is runnable in R5-M source/runtime scope: its platform-gated main loads an installation policy sidecar, acquires an audit-session `flock` singleton, binds a private Unix socket, verifies exact kernel peer/audit-token and Security.framework code identity, performs no-UI Keychain-backed protocol-v1 authentication, and attaches only authenticated streams to `ProductionRuntime`. The R6 gateway owner client and R7 strict Electron/helper protocol-v10 supervision are implemented in source scope. R8-M now adds the macOS-only installed path: a nested macOS 13+ `SMAppService` LoginItem, local self-signed/ad-hoc packaging policy, exact gateway socket client, no-UI Keychain trusted-application provisioning, durable maintenance persistence, outer-bundle removal detection, and recursive package/architecture inspection. See `macos-local-owner-install.md`. Native LoginItem, ACL denial, TCC, update-replacement, and physical-input execution on the friend's x64/ARM64 Macs remain acceptance evidence; cross-compilation is not a native pass.
